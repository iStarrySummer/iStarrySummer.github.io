# Markdown 教程文章设计说明

## 意图

在现有 Fuwari 博客发布一篇中文 Markdown 入门教程，让读者能够从一篇连贯文章中理解并看到常用语法的实际渲染效果；文章同时作为站点 Markdown 能力的检查页，但不改变博客现有主题、布局或功能。

## 目标

- 文章采用循序渐进的教程写法，而不是孤立语法片段的堆叠。
- 覆盖六级标题、段落、粗体、斜体、删除线、行内代码、有序和无序列表、嵌套列表、任务清单、引用、链接、图片、表格、分隔线、代码块、数学公式、脚注、转义字符，以及项目现有的提示块、剧透文本、GitHub 仓库卡片和 Expressive Code 展示能力。
- 使用 Fuwari 既有 frontmatter，设置中文标题、摘要、分类与标签，并以正式文章状态发布。
- 构建通过后推送到 `iStarrySummer/iStarrySummer.github.io`，等待 GitHub Pages 部署成功，再以真实浏览器验证桌面端和移动端。

## 非目标与反目标

- 不新增 Markdown 插件或其他依赖，不修改主题配色、字体、组件、动画、导航及页面结构。
- 不为追求覆盖率而使用项目当前无法稳定渲染的扩展语法。
- 不修改已有的上游类型错误，也不借此任务重构无关代码。
- 不增加新的站点功能，文章中的外部资源仅使用可靠且与教程内容直接相关的内容。

## 约束

- 文章存放在 `src/content/posts/`，并严格符合 `src/content/config.ts` 的内容集合 schema。
- 仅使用仓库当前已配置的 Markdown、Remark/Rehype、KaTeX、Expressive Code 和 Fuwari 扩展能力。
- 保留原项目许可证、版权声明和页脚上游链接。
- 远程写入前必须确认 `gh api user --jq .login` 返回 `iStarrySummer`，并核对 Git 远端为该账号的 Pages 仓库。

## 方案比较与选择

方案一是“可阅读的中文入门教程”，以真实写作场景串联语法，读者可以顺序学习，语法覆盖通过章节和示例自然展开；优点是文章可长期阅读和分享，代价是篇幅略长。方案二是“完整语法展示页”，按语法类型集中陈列最短示例，查找更快，但可读性较弱，也更像测试页。用户选择方案一，因此文章将以教程为主，同时在不破坏阅读连贯性的前提下尽量完整覆盖 Fuwari 已支持的语法。

## 实现设计

文章暂定标题为《Markdown 从入门到进阶：一篇文章掌握常用语法》，正文按“基础排版 → 内容组织 → 链接与媒体 → 表格与代码 → 数学与扩展语法 → 综合示例”的顺序推进。每个语法点先说明用途，再给出可直接复制的源码或渲染示例；代码区使用项目现有 Expressive Code 标题、行高亮与差异标记能力，扩展部分使用 Fuwari 现有 admonition、spoiler 和 GitHub repository card。文章图片优先引用仓库中已存在且适合教程展示的本地资源，避免增加无关素材或依赖外部不稳定图片。

## 验收

本地生产构建必须成功，生成的文章路由、首页文章卡片及 frontmatter 信息必须正确。浏览器验证需覆盖文章正文的标题层级、列表、引用、链接、图片、表格、代码高亮、公式、脚注、提示块、剧透和仓库卡片，并分别检查桌面宽度与移动端宽度下是否存在溢出、遮挡或导航异常。远端 GitHub Pages 工作流成功且线上文章可访问后，才视为发布完成。
