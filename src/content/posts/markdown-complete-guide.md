Markdown 是一种轻量级标记语言，它用少量易读的符号描述文章结构，再由博客系统把这些符号转换成排版完整的网页。它的价值不在于“少按几个按钮”，而在于让内容本身保持清晰：即使离开编辑器，源文件依然能够直接阅读、搜索和进行版本管理。这篇文章从最常用的写法开始，逐步介绍本博客当前支持的 Markdown 基础语法、代码展示、数学公式和扩展组件。

:::note[阅读方式]
每一节先解释语法的用途，再展示实际渲染结果。需要查看原始写法时，可以对照紧随其后的代码块；复制示例后替换其中的文字，就能用于自己的文章。
:::

## 一、标题与段落：先建立文章骨架

标题用来表达内容的层级。Markdown 在行首使用 `#` 表示标题，井号越少，层级越高；`#` 与标题文字之间必须保留一个空格。一篇文章通常只有一个一级标题，正文再依次使用二级和三级标题，不应单纯为了改变字号而跳级。

````markdown title="标题语法.md"
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
````

下面是六个层级的实际效果。本文已经有文章标题，因此这里的一级标题只用于展示语法。

# 一级标题示例

## 二级标题示例

### 三级标题示例

#### 四级标题示例

##### 五级标题示例

###### 六级标题示例

普通段落之间要留一个空行。如果只是直接换行，Markdown 通常仍会把两行合并为同一段；若确实需要在段内换行，可以在第一行末尾输入两个空格。下面两句话属于同一段，但第一行末尾保留了两个空格：  
第二行会从新的一行开始。

````markdown
这是第一段，它可以包含多句话。

这是第二段。
第一行末尾添加两个空格后  
这里会在同一段中换行。
````

## 二、强调、删除线与行内代码

行内样式用于强调句子中的局部信息。两个星号包围文字得到**粗体**，一个星号得到*斜体*，三颗星号可以得到***粗斜体***，两个波浪号得到~~删除线~~。文件名、命令和变量适合写成行内代码，例如 `src/content/posts/`、`pnpm build` 和 `const title = "Markdown"`。

````markdown
**这是粗体**
*这是斜体*
***这是粗斜体***
~~这是删除线~~
请运行 `pnpm build` 完成构建。
````

当星号、井号或反引号本身就是内容时，在前面加反斜杠可以阻止 Markdown 解释它们。例如，\*这对星号会原样显示\*，\# 也不会变成标题，\`code\` 不会变成行内代码。反斜杠转义适合教程、正则表达式说明和需要讨论 Markdown 源码的场景。

## 三、列表与任务清单

无序列表可以使用 `-`、`*` 或 `+`，同一篇文章最好保持一种写法。有序列表使用数字和句点；渲染时浏览器会自动编号，因此源文件中连续使用 `1.` 也可以。子列表至少缩进两个空格，实际项目中使用四个空格通常更清晰。

- 写下主题
- 收集资料
    - 保存参考链接
    - 记录关键结论
- 完成初稿

1. 创建 Markdown 文件
2. 填写文章信息
3. 编写正文
    1. 先搭建标题结构
    2. 再补充示例
4. 本地预览并发布

````markdown
- 一级项目
    - 二级项目
    - 另一个二级项目

1. 第一步
2. 第二步
    1. 子步骤
````

任务清单是在无序列表中加入方括号：空格表示未完成，`x` 表示已完成。它非常适合记录文章发布流程。

- [x] 确定文章主题
- [x] 编写语法示例
- [ ] 检查移动端排版
- [ ] 发布文章

````markdown
- [x] 已完成任务
- [ ] 待完成任务
````

## 四、引用与嵌套引用

引用块使用 `>` 开头，适合摘录资料、强调定义或展示他人的观点。连续多行可以组成同一个引用块，空白引用行写成单独的 `>`。在第二层继续添加 `>`，就能形成嵌套引用。

> 写作不是把想到的内容全部放进文章，而是为读者保留一条清晰的理解路径。
>
> > 当一段内容需要补充背景时，可以在引用内部继续嵌套。

````markdown
> 第一层引用。
>
> > 第二层引用。
````

引用内部仍然可以使用**强调**、`行内代码`、链接和列表，因此它不只是一个特殊颜色的段落，而是一个能够承载完整 Markdown 内容的容器。

## 五、链接、自动链接与图片

普通链接由方括号中的说明文字和圆括号中的地址组成，例如 [本博客项目仓库](https://github.com/iStarrySummer/iStarrySummer.github.io)。说明文字应描述目标内容，不要只写“点击这里”，这样对搜索引擎和使用屏幕阅读器的读者都更友好。若希望直接显示完整网址，可以写成自动链接：<https://github.com/iStarrySummer>。

````markdown
[本博客项目仓库](https://github.com/iStarrySummer/iStarrySummer.github.io)
<https://github.com/iStarrySummer>
[跳转到本文的表格章节](#六表格让结构化信息更清楚)
````

站内章节链接通常指向标题自动生成的锚点。例如，[跳转到代码块章节](#七代码块与语法高亮) 会把读者带到本文后面的代码示例。

图片语法是在链接语法前加一个感叹号。方括号中的替代文本会在图片无法加载时显示，也会被辅助技术朗读；圆括号中写图片路径，还可以在地址后添加可选标题。

![仲夏的博客头像](https://zhongxia-knowledge-base-lrs.oss-cn-beijing.aliyuncs.com/img/profile-avatar.png "仲夏的博客头像")

````markdown
![仲夏的博客头像](https://zhongxia-knowledge-base-lrs.oss-cn-beijing.aliyuncs.com/img/profile-avatar.png "仲夏的博客头像")
````

:::tip[图片路径]
图片先通过 PicGo 上传到图床，再把生成的 HTTPS 地址写进 Markdown。发布工具会原样保留远程 URL，因此写作目录只需要保存模板和文章文件。
:::

## 六、表格：让结构化信息更清楚

表格由竖线分隔单元格，第二行的连字符负责分隔表头和正文。冒号可以控制对齐方式：左侧冒号表示左对齐，两侧都有冒号表示居中，右侧冒号表示右对齐。

| 语法 | 典型用途 | 学习难度 |
| :--- | :---: | ---: |
| 标题与段落 | 组织文章结构 | 低 |
| 链接与图片 | 引用外部或本地资源 | 低 |
| 代码块 | 展示程序和命令 | 中 |
| 数学公式 | 书写推导与符号 | 中 |

````markdown
| 语法 | 用途 | 难度 |
| :--- | :---: | ---: |
| 标题 | 组织结构 | 低 |
| 代码块 | 展示代码 | 中 |
````

为了让源文件容易维护，竖线不必严格对齐，但每一行应保持相同的列数。单元格内容较长时，移动端通常会通过横向滚动或自动换行保持可读性。

## 七、代码块与语法高亮

行内代码适合短命令，连续三颗反引号组成的围栏代码块则适合多行内容。在开头的反引号后写语言名，渲染器就能进行语法高亮。

```javascript title="greeting.js" {2}
const reader = "Markdown 学习者";
console.log(`你好，${reader}！`);
```

上面的代码块使用 `title="greeting.js"` 显示文件名，并用 `{2}` 高亮第二行。原始写法如下；外层示例使用四颗反引号，因此内部的三反引号不会提前结束代码块。

````markdown
```javascript title="greeting.js" {2}
const reader = "Markdown 学习者";
console.log(`你好，${reader}！`);
```
````

Expressive Code 还可以用 `ins`、`del` 标出新增和删除的行。下面的示例表示把普通输出替换成更明确的问候语。

```javascript title="message.js" del={2} ins={3}
function greet(name) {
  console.log(name);
  console.log(`你好，${name}！`);
}
```

当样板代码较长时，可以折叠暂时不需要关注的行。读者仍然可以展开查看完整内容。

```javascript title="article.js" collapse={1-4} {7}
import { readFile } from "node:fs/promises";

const sourcePath = "article.md";
const encoding = "utf8";

async function loadArticle() {
  const content = await readFile(sourcePath, encoding);
  return content.trim();
}

console.log(await loadArticle());
```

终端命令可以标注为 `bash`，配置文件可以标注为 `yaml` 或 `json`。语言名称只影响高亮与标签，不会真的执行代码。

```bash title="构建博客"
pnpm install
pnpm build
pnpm preview
```

## 八、数学公式

数学公式由 KaTeX 渲染。行内公式使用一对美元符号，例如质能方程 $E = mc^2$ 可以自然嵌入句子；独立公式使用两对美元符号，适合需要突出展示的推导。

$$
\sum_{k=1}^{n} k = \frac{n(n+1)}{2}
$$

如果等差数列首项为 $1$、末项为 $n$，共有 $n$ 项，那么平均值为 $\frac{1+n}{2}$，所以总和是 $n \times \frac{1+n}{2}$，与上式一致。

````markdown
行内公式：$E = mc^2$

独立公式：

$$
\sum_{k=1}^{n} k = \frac{n(n+1)}{2}
$$
````

:::warning[美元符号的歧义]
普通文本中的货币符号也可能被解释成公式定界符。连续出现价格时，建议转义美元符号，或者改用“元”等不会产生歧义的单位。
:::

## 九、脚注

脚注可以把补充说明移到正文末尾，避免打断主要论述。正文中写一个脚注引用[^markdown]，再在任意位置定义对应内容；渲染器会自动生成编号、跳转链接和返回正文的按钮。

同一段还可以引用另一条说明[^blog]。脚注标识只在源文件中用于对应关系，最终编号由出现顺序决定，因此修改文章时不需要手动重排数字。

````markdown
Markdown 适合保存纯文本内容[^plain-text]。

[^plain-text]: 纯文本文件便于搜索、比较差异和长期保存。
````

[^markdown]: Markdown 最初由 John Gruber 与 Aaron Swartz 共同设计，目标是让纯文本本身也保持易读。
[^blog]: 本博客在基础 Markdown 之上配置了数学公式、Expressive Code 和提示块等能力。

## 十、博客提示块

提示块也称 Admonition（告示框），它用不同的视觉样式表达补充信息、技巧或风险。当前主题支持 `note`、`tip`、`important`、`warning` 和 `caution` 等类型；标题可以省略，也可以写在方括号中。

:::note
`note` 适合补充背景和上下文，不应承载正文唯一的一份关键结论。
:::

:::tip[写作技巧]
先完成文章结构，再逐节补充示例，通常比从第一句话一路写到底更容易保持层次。
:::

:::warning
从网页复制 Markdown 时，要检查弯引号、全角标点和不可见空格，它们可能使代码或链接失效。
:::

````markdown
:::note[自定义标题]
这里填写提示内容。
:::
````

当前主题也兼容 GitHub 风格的提示语法：

> [!NOTE]
> 这种写法在 GitHub README 与本文中都能得到醒目的提示效果。

````markdown
> [!NOTE]
> 这里填写提示内容。
````

## 十一、隐藏文本、仓库卡片与 HTML

剧透文本可以先隐藏答案或补充内容，读者点击后再查看。例如，当前博客的品牌是 :spoiler[Amor.]。

````markdown
答案是 :spoiler[Markdown]。
````

GitHub 仓库卡片会在页面加载时读取仓库的公开信息，适合在项目介绍中提供比普通链接更丰富的入口。

::github{repo="iStarrySummer/iStarrySummer.github.io"}

````markdown
::github{repo="iStarrySummer/iStarrySummer.github.io"}
````

Markdown 允许嵌入一部分 HTML。下面使用原生的 `<details>` 和 `<summary>` 创建折叠区域；这种能力适合偶尔补充长内容，但频繁混用 HTML 会降低源文件的可读性。

<details>
<summary>展开查看隐藏的发布检查项</summary>

- 本地构建是否成功
- 链接和图片是否可访问
- 桌面端与移动端是否都能正常阅读

</details>

````html
<details>
<summary>展开标题</summary>

这里可以继续写 Markdown 内容。

</details>
````

## 十二、分隔线、注释与容易混淆的细节

三个或更多连字符、星号或下划线可以生成分隔线。为了避免与标题或列表混淆，建议在分隔线前后各留一个空行。

---

Markdown 没有统一的“可见注释”语法；需要留下不会出现在页面中的说明时，可以使用 HTML 注释。

<!-- 这是一条写给文章维护者的注释，不会显示在渲染页面中。 -->

````markdown
正文内容。

<!-- 这是一条不会显示在页面中的维护说明。 -->

---
````

连续数字加句点可能被识别成有序列表，行首井号可能被识别成标题，成对美元符号可能被识别成公式。遇到这些边界情况时，先检查空格和空行，再考虑使用反斜杠转义。

## 十三、把语法组合成一段完整内容

单独掌握语法之后，更重要的是让它们共同服务于表达。下面用一个简短的学习记录把标题、任务清单、引用、链接、代码和脚注组合起来。

### 今日学习记录

我今天阅读了 [本博客项目仓库](https://github.com/iStarrySummer/iStarrySummer.github.io)，并完成了以下练习：

- [x] 理解标题层级
- [x] 编写一个表格
- [x] 为代码添加语言标记
- [ ] 独立完成下一篇文章

> 保持源文件清晰，比堆叠大量样式更重要。

```typescript title="progress.ts" {3}
const completed = 3;
const total = 4;
console.log(`学习进度：${completed}/${total}`);
```

当前完成率为 $\frac{3}{4}=75\%$。明天继续练习脚注和提示块[^practice]。

[^practice]: 最有效的练习方式，是用 Markdown 真正写完并发布一篇文章。

## 结语

Markdown 的核心可以概括为三点：用标题建立层级，用列表、引用和表格组织信息，用链接、图片、代码与公式补充证据。本博客配置的提示块、剧透、仓库卡片和 Expressive Code 在此基础上增强了表达能力，但它们仍然应该服务于内容，而不是取代内容。先写出清晰的纯文本结构，再逐步加入必要的扩展语法，通常就能得到一篇既容易维护、又具有良好阅读体验的文章。
